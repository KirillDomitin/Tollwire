Фича: $ARGUMENTS

Работай строго по шагам. На каждом **СТОП** — остановись, покажи результат и жди ответа пользователя; молчание
или «продолжай» без выбора не считается выбором варианта.

1. **Проект.** Вызови агента `architect` с описанием фичи. Покажи пользователю коротко: варианты, рекомендацию,
   риски.
   **СТОП:** пользователь выбирает вариант или правит план.
2. **План.** Сохрани принятый план в `docs/plans/<короткое-имя>.md`: задача в 1–2 предложениях, принятое решение,
   шаги с чекбоксами `- [ ]` (файл/модуль → что меняется), риски. После любого `/clear` работа продолжается по
   этому файлу.
3. **Красные тесты.** Вызови агента `tester`: тесты по плану до реализации. Убедись, что они падают по ожидаемой
   причине, а не из-за ошибки в самом тесте.
   **СТОП:** покажи список тестов (файл → что ловит), пользователь подтверждает.
4. **Реализация — по одному шагу плана.** После каждого шага: агент `test-runner` (затронутые тесты), отметка
   `- [x]` в плане, коммит с понятным сообщением. Тесты не запускай напрямую в этой сессии — только через
   `test-runner`.
   Шаг затрагивает реальные серверы (SSH, живой прогон) — **СТОП:** нужно явное согласие пользователя.
   Если по ходу план оказался неверным — **СТОП:** опиши расхождение и предложи правку плана.
5. **Ревью.** Вызови агента `reviewer` по `git diff master`. Исправь подтверждённые находки, снова `test-runner`;
   затем `test-runner` с полным прогоном. Миграции — проверить upgrade и downgrade.
   **СТОП:** покажи находки ревью, что исправлено и итог полного прогона.
6. **Документация.** Вызови агента `doc-writer`. Покажи список изменённых документов. В плане отметь, что фича
   готова.

Мелкие правки (опечатка, текст ошибки, одно условие) этот процесс не требуют — их делают обычным запросом.
