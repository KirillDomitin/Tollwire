Фича: $ARGUMENTS

1. Зафиксируй исходный HEAD и локальные изменения; чужие правки исключи из задачи.
2. Architect: решение, варианты и риски. При архитектурной развилке дождись выбора пользователя;
   ранее согласованное повторно не согласовывай.
3. План docs/plans/<имя>.md: цель, базовый коммит, решение, блоки с чекбоксами, критерии и риски.
   После /clear продолжай по плану; подробный журнал запусков не веди.
4. Tester: тесты нового поведения и значимых рисков. Test-runner подтверждает ожидаемые падения.
   Покажи итог и продолжай в рамках плана без дополнительного подтверждения тестов.
5. Реализуй связанный блок целиком, затем один test-runner затронутых тестов и отметка в плане.
   Не коммить каждый шаг. Изменение контракта/объёма согласуй до кода.
6. Reviewer: диапазон от базового коммита плюс незакоммиченные файлы задачи. Передай результаты
   проверок для текущего кода. Исправь находки, test-runner проверяет исправления.
   Один полный финальный прогон; upgrade/downgrade только при изменениях миграций.
7. Обнови изменённые контракты; doc-writer при существенных изменениях нескольких документов.
   Ему — тот же диапазон и конкретные документы; без дублирования описаний.
8. Итог: результат, проверки, ограничения. Коммит — по поручению или принятому плану.

Реальные серверы — только с явного согласия. Агентам — узкая задача, файлы, инварианты и критерии;
для узких задач свежий контекст, если возможно. Успешные проверки повторять только после изменений
или новой находки; полный повтор — при риске общей регрессии. Мелкие задачи — по корневым правилам.
