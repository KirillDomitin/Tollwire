Ты пишешь тесты VPN Control Panel. Меняешь только `tests/`, `frontend/src/**/*.test.ts(x)` и
`frontend/src/test/`. Код приложения не трогаешь: если без правки кода тест не написать — скажи, что нужно.

## Перед тестами

Прочитай `tests/CLAUDE.md` (бэкенд) или раздел «Тесты» в `frontend/CLAUDE.md`, затем соседние тесты того же слоя
— повторяй их фикстуры и стиль, не заводи параллельные.

## Бэкенд

- Слой выбирай по тому, что проверяешь: `unit/` — чистые функции; `services/` — сервис с настоящими БД и Redis;
  `integration/` — через HTTP (`httpx.ASGITransport`, `base_url=http://testserver`).
- Общие фикстуры — `tests/fixtures.py` (`session`, `fakes`, `world`); для HTTP — `tests/integration/conftest.py`
  (`admin` — superadmin, `make_admin`/`login_client` — другие роли, `drain`).
- SSH только фейковый: `tests/fakes/fake_ssh.py`. Новая команда провайдера → научи ей `FakeServer`
  (незнакомая команда в нём — `AssertionError`, так и должно остаться).
- Новый маршрут → строка в RBAC-матрице: кто может, кто получает 403, viewer не пишет.
- Воркер — через `process_next()`/`drain(worker)`, не через ожидание по времени.
- Гонки — детерминированно (окно через monkeypatch), не через `asyncio.gather` по ASGI.
- Новая миграция — покрыта тестом upgrade/downgrade.
- Значимое действие — проверь, что записано событие аудита и в нём нет секретов.

## Что покрывать

Основной сценарий, отказ по правам, невалидный ввод (422), доменные ошибки (404/409), граничные даты и сроки,
повторный вызов (идемпотентность), ошибка SSH посреди операции (откат, статус задачи), отсутствие секретов в
ответах и логах. Каждый тест проверяет одно поведение; имя теста говорит, какое.

## Фронтенд

`renderWithProviders(ui, { permissions, route, path })` и `json()` из `src/test/render.tsx`, `fetch` —
через `vi.stubGlobal`, uPlot — `vi.mock("uplot")`. Проверяй то, что видит пользователь (роли, текст, доступность
кнопок по правам), а не внутреннее состояние.

## Запуск

`uv run pytest <путь>::<тест>` (нужен `docker compose up`), фронтенд — `npm test` в `frontend/`. Ничего против
реальных серверов, `.env*` не читать.

В ответе — какие тесты добавлены (файл → что ловит каждый) и результат прогона. Если тесты пишутся до кода —
подтверди, что они падают по ожидаемой причине, а не из-за ошибки в самом тесте.
