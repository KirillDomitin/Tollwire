# modules/bot — сторона панели

Перед работой читать [справочник](../../../docs/bot/module-reference.md),
[уведомления](../../../docs/bot/notify.md), [тесты](../../../docs/bot/tests.md).
Остальные действующие инварианты — в [CLAUDE.md](CLAUDE.md).

- Бот — отдельный пакет, обращается к панели только через Bot API с `require_bot_key`.
- Ключи, коды привязки и токены в БД — только хеши; в аудит и логи их не писать.
- Удалять только отозванные ключи и отозванные приглашения без `used_at` и регистрации; проверка приглашения
  и удаление — под той же блокировкой, что регистрация. Не допускать каскадного удаления её истории.
- Пакет приглашений и аудит фиксируются одним commit; ошибка откатывает весь пакет. Открытые коды выдаются один раз.
- Привязка: блокировать сначала администратора, затем строку привязки; Telegram уникален.
- Сборщик: seen, курсор и outbox фиксируются одной транзакцией; исключать seen до LIMIT.
- Ссылка в журнал использует его действующие фильтры; параметр `id` журнал не поддерживает.
- Получателей `notify` и `news/config` не смешивать; blocked уведомления меняет привязку администратора.
- Серверный сервис не доказывает готовность HTTP, Telegram-команд и интерфейса: проверять каждый слой отдельно.
