# modules/geoip - список российских префиксов (этап 24.4)

Список IPv4-сетей России для «России напрямую» на шлюзе (`modules/gateway/CLAUDE.md`, раздел 24.4): клиенты шлюза,
идущие на российские адреса, выходят с адреса самого шлюза, остальное - через назначенный выход. Здесь - получение и
проверка списка, исключения администратора и постановка применения на шлюзы. Применение на сервере - `gateway/ru.py`
и `infrastructure/vpn/CLAUDE.md`.

**Справочник** (карта файлов, модели, API, операции: Таблицы, API, Аудит) — `docs/geoip/module-reference.md`, читать по необходимости.

## Источник и разбор (`parser.py`, чистые функции)

- Источник - RIPE `delegated-ripencc-extended-latest` (адрес в настройках `GEOIP_SOURCE_URL`, только https). Строки
  `ripencc|RU|ipv4|<начало>|<число адресов>|<дата>|<статус>`, статусы `allocated` и `assigned`; число адресов не обязано
  быть степенью двойки: диапазон разбивается `summarize_address_range`, затем `collapse_addresses`. IPv6, ASN, чужие
  страны, `reserved` / `available`, заголовок и сводки пропускаются (в итоге `skipped`).
- Загрузка админа (`POST /upload`) - тот же файл RIPE или CIDR по строке; тот же разбор и те же правила.
- Строгость: список принимается, только если валидных записей не меньше 1000, а префиксов после сжатия от 3000 до 30000;
  иначе 422 / падение задачи с понятным текстом. Строка мусора пропускается (`skipped`). Сеть, ПЕРЕСЕКАЮЩАЯСЯ с любым из
  зарезервированных диапазонов (0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.88.99/24,
  192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/3), или крупнее /12 (реальные российские блоки не крупнее /13)
  отбрасывается и считается в `rejected` (источник RIPE из-за одной строки не валится). Загрузка админа строгая: любая такая
  сеть - 422 на весь файл. 172.0.0.0/8, 169.0.0.0/8 или 100.0.0.0/8 пересекают зарезервированное и не проходят, хотя их
  крайние адреса публичны. Единый источник правды - `infrastructure/vpn/split_routes.py` (его же использует шлюз при записи
  `ru.prefixes`). Версия - самая поздняя дата записей (`YYYYMMDD`).
- Список хранится нормализованным (`render_list`: CIDR по строке, по возрастанию); `sha256` считается от этого текста.

## Правила активации (`service.py`, `GeoipService`)

- Первый список активируется сам. Дальше (`requires_confirmation`): изменение числа префиксов ИЛИ числа покрытых адресов
  больше 20% от активного, ЛИБО осталось меньше 80% адресов активного списка, ЛИБО больше 20% адресов нового списка раньше не
  входили в активный (замена части сетей на чужие при тех же суммах ловится пересечением) - список сохраняется кандидатом
  (`CANDIDATE`) и ждёт `POST /geoip/{id}/activate`; иначе активируется сам, прежний становится `SUPERSEDED`. Тот же sha256, что у активного, - `unchanged` (ждущий кандидат при этом устаревает: `SUPERSEDED`); тот же кандидат - не
  дублируется; новый кандидат заменяет ожидающего (тот `SUPERSEDED`). Подмена или поломка источника не должна молча
  перестроить маршрутизацию всех шлюзов. Кандидат на шлюзы не идёт.
- Один `ACTIVE` на всю панель гарантирует частичный уникальный индекс `uq_geoip_lists_one_active`; прежний активный
  переводится в `SUPERSEDED` и сбрасывается (flush) до вставки нового. Приём списка начинается с `SELECT ... FOR UPDATE`
  активного списка (два одновременных приёма идут по очереди); если оба видели «списка нет», проигравшего останавливает индекс:
  `IntegrityError` -> откат -> `StateConflictError` (409 «try again»). Разбор файла до 5 МБ и сравнение с активным идут в
  `asyncio.to_thread` (`_prepare`): event loop API не блокируется.
- Эффективный список для шлюза = ((активный ∪ DIRECT) − зарезервированные диапазоны − TUNNEL − адреса этого шлюза и его
  выходов /32) (`effective_list`, `GeoipService.effective_prefixes(server_id)`); вычитаемая сеть внутри крупной разбивает
  её на оставшиеся куски (`split_routes.subtract`). Адреса - `servers.host` шлюза и серверов-выходов, если это IPv4 (имя хоста
  панель не резолвит: такой сервер от DIRECT не защищён). Испорченные данные в БД - `GeoipError` / `ValueError`; вызывающие
  (`gateway/ru.py`) превращают их в issue / проваленную проверку `ru` / ошибку задачи с фиксированным текстом без строк списка.
- После активации и после любого изменения исключений каждому серверу со шлюзом и SSH-учёткой ставится задача
  `gateway_apply_ru` (`schedule_apply_all`); пока по серверу есть незавершённая такая же, новая не ставится - она применит
  уже актуальный список. Нет активного списка - ничего не ставится.

## Задача `geoip_update` и планировщик

`GEOIP_UPDATE` - глобальная задача (без `server_id`, без `ServerLock`): воркер скачивает файл
(`infrastructure/geoip.py`: только https, редирект на не-https запрещён, потоковое чтение с обрывом на 20 МБ, таймаут из
настроек, адрес только из настроек - пользовательского ввода нет) и принимает его теми же правилами. В `result` - итог
(`status`, `prefixes`, `version`, `sha256`, `skipped`). Правило планировщика `geoip` (раз в неделю,
`GEOIP_UPDATE_INTERVAL_SECONDS`, 0 - выключено) ставит задачу, только когда на панели есть хотя бы один шлюз. Скачивание ограничено
общим сроком чтения 300 с (`read_limited`), обрыв тела (`http.client.IncompleteRead` и другие `HTTPException`) - обычная
`DownloadError` с именем типа ошибки, без сырого текста в `job.error`. Установка шлюза, когда активного списка ещё нет,
ставит `GEOIP_UPDATE` (без дублей).

## Ограничения

- Страна в RIPE - страна РЕГИСТРАЦИИ блока, а не расположения сервера: российский хостер может держать сети за рубежом и
  наоборот. CDN и облака (Cloudflare, Google, Яндекс.Облако за рубежом и т. п.) отдают российским пользователям адреса вне
  списка: такие сервисы пойдут через выход. Спасают исключения `direct` / `tunnel`.
- DNS клиентов идёт через выход (адрес DNS не в списке), поэтому российские сайты могут получать зарубежные адреса от
  геозависимого DNS; для точной картины нужен DNS шлюза (не сделан).
- Список проверяет сама панель, но источник доверенный лишь по https: подмена файла в пределах 20% пройдёт без админа.
