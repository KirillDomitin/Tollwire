# До пяти конфигов шлюза на VPN-пользователя

## Цель и исходное состояние

Один пользователь получает отдельный конфиг/peer шлюза для каждого устройства, максимум пять.
Это ограничение числа выданных конфигов, а не распознавание физических устройств по одному ключу.

База исследования: `12efbb09ec92f3503a598bf90bd7583fb8d908ad`.
До начала задачи уже изменён `docs/development/improvements-plan.md` и есть незакоммиченный
`docs/development/server-clients-task.md`; сохранить эти правки.

## Правила и выбранный объём

- Владелец лимита — `VPNUser`. Считать только конфиги `AMNEZIA_GATEWAY`, суммарно по всем шлюзам.
- Один credential соответствует одному конфигу шлюза с собственным ключом.
- Ожидающая выдача резервирует место до SSH. Отзыв освобождает место после подтверждённого удаления peer.
- Неоднозначный сбой SSH не освобождает место до подтверждённой уборки/сверки.
- Повторный показ, скачивание и новая ссылка на существующий конфиг не создают устройство.
- Действующие конфиги сохраняются. Уже существующее превышение лимита не удаляется автоматически;
  новую выдачу блокировать до освобождения места.
- Истечение подписки запрещает новую выдачу и отзывает все конфиги, включая незавершённые выдачи.
- Прямые AWG и импортированные APP-протоколы не переводить на шлюзы автоматически; прежнюю политику сохранить.

Пользователь выбрал управление через оба интерфейса: пользователь через Telegram-бота,
администратор через веб-панель. Повторно этот выбор не запрашивать.
12 ноября работа остановлена пользователем до изменения кода приложения; подготовлен только план.
13 ноября поручено разбить план на этапы и подготовить задание для нового чата, без начала реализации.

## Архитектура

Architect рекомендует расширить lifecycle существующего `VPNCredential`, без отдельной таблицы устройств:
резервировать целевой credential до SSH и разрешать отсутствие конфига/ключа/адреса только в предусмотренных
состояниях незавершённой выдачи. Финальные поля и ограничения зафиксировать перед написанием тестов.
Места резервируются транзакционно под блокировкой строки `VPNUser`, включая разные шлюзы.

Существующие singleton-методы credentials заменить подходящими списками/exists. Сохранить прежнюю
политику одиночного клиента для других протоколов. Задачи создания/индивидуального отзыва должны
адресовать конкретный `credential_id`, а не «единственного клиента grant».

Имя peer строится из стабильного UUID, не пользовательской подписи устройства. При повторах задачи
обрабатывать тот же целевой credential; старые grant-based имена поддержать в sync. При выдаче,
сохранённой в БД, повтор не должен менять ключи или создавать второе устройство. Если SSH создал peer,
но результат не сохранён, сначала подтвердить уборку соответствующей незавершённой выдачи.

Индивидуальный отзыв снимает только выбранное устройство. Отзыв grant/подписки снимает все его
credentials и обрабатывает ожидающие выдачи. Назначения шлюза уже привязаны к credential_id.

В панели — список устройств, занято/5, добавление, показ и отдельный отзыв. В боте —
выбор конкретного устройства для ссылки и общая резервация при регистрации/добавлении. API бота
проверяет принадлежность устройства пользователю; `bot/` не импортирует `src/`.

## Миграция и совместимость

Старые записи/ключи/конфиги сохранить. Обновить уникальные ограничения и check-constraints под
новый lifecycle. Старый воркер не должен одновременно обрабатывать задачи с новым target-смыслом.

Downgrade не удаляет лишние credentials. Если данные несовместимы со старым unique live/grant,
он явно отказывает: оператор сначала штатно отзывает дополнительные устройства и завершает уборку.
Проверить допустимые upgrade/downgrade и отказ на несовместимых данных.

## Критерии готовности

- Пять занятых мест блокируют шестой запрос. При четырёх местах два параллельных запроса,
  в том числе на разных шлюзах, занимают только одно оставшееся место.
- Повтор задачи не создаёт дубликат, сбой назначения выхода чинится для того же credential.
- SSH timeout после создания peer не оставляет свободное место для шестого клиента.
- Отзыв одного не затрагивает другие устройства; отзыв подписки и истечение срока снимают все.
- Sync восстанавливает несколько корректных peers, понимает legacy-имена и убирает сироты.
- Просмотр существующего конфига не занимает слот; выбор в панели/боте возвращает нужный конфиг.
- Секреты только зашифрованы, не попадают в API списков, аудит и журналы.
- Ruff/mypy, проверки backend/frontend/бота, upgrade/downgrade и независимое ревью проходят.

Живые VPN-серверы — только после явного согласия. Коммит, пуш и деплой — по отдельному поручению.
