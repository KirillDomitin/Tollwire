# Доработки панели бота

## Задача и решение

Добавить удаление отозванных API-ключей и приглашений, список получателей рассылок и массовый выпуск приглашений.
Пользователь выбрал вариант А: удалять только отозванные неиспользованные приглашения; использованные и их регистрации сохранять. Миграция БД не требуется.

Массовый выпуск: количество 1–100 (по умолчанию 1), общие протокол, срок доступа, срок действия и примечание. Отдельный POST `/api/v1/bot-admin/invites/batch` не меняет контракт одиночного выпуска. Все записи и аудит фиксируются одной транзакцией. Результат показывается один раз, все ссылки/коды можно скопировать вместе.

## Риски и доказательства

- Каскадное удаление регистрации: запрещать удаление при used_at или наличии регистрации, проверить сохранность регистрации/пользователя/доступа и гонку регистрации.
- Пакет не должен частично фиксироваться: ошибка промежуточной вставки откатывает приглашения и аудит. Проверить 1/100, отказ 0/101/дробного количества, уникальность и хеширование кодов.
- Открытые коды/ссылки не попадают в аудит, логи, query-кеш или хранилище браузера; результат мутации gcTime=0, очистка при закрытии. Без username выдаются коды.
- Потеря ответа не означает отсутствие выпущенных приглашений: не повторять POST автоматически, обновить метаданные списка при ошибке, ясно описать одноразовую выдачу.
- Список получателей не должен обрываться первой страницей: проверить пагинацию, одинаковые имена, поиск и сохранение выбора; недоступных исключает существующий серверный расчёт/очередь.
- Активные ключи и приглашения не удаляются, права BOT_KEYS/BOT_MANAGE сохраняются, просмотр не даёт права изменения. Одиночный API и CLI совместимы.

Реальные серверы, SSH и VPN-конфиги эта работа не затрагивает. Деплой требует отдельного явного согласия.
