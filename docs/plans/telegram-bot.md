# ТЗ: Telegram-бот панели (этап 25)

Статус: согласовано, к реализации по этапам ниже (каждый — отдельным `/feature`).

## 1. Цель

Пользователь получает VPN сам, без админа: открывает пригласительную ссылку в Telegram, указывает имя и почту,
получает ссылку на страницу со своим конфигом. Админ из панели делает рассылки (новости, конфиги) и получает
в Telegram уведомления о недоступности серверов и самой панели.

Сейчас сервис только «для своих»: регистрация по приглашениям, без оплаты. Оплата появится позже — между
регистрацией и выдачей ссылки, без переделки остального (см. 6.3).

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Где работает бот | Всегда выбор: на сервере панели (вариант 1) или на отдельном сервере (вариант 3). Установка на VPN-сервер панели по SSH (вариант 2) — позже, этап 25.7. Панель может стоять в РФ, где Telegram недоступен. |
| Связь бот ↔ панель | Только бот → HTTPS API панели, по ключу бота. Панель никогда не обращается ни к Telegram, ни к боту. Токен Telegram хранится только у бота. |
| Регистрация | Только по приглашению (одноразовая ссылка `t.me/<бот>?start=<код>`). Без кода — «сервис в закрытом тестировании». |
| Данные пользователя | Имя, почта (обязательна, уникальна — как сейчас `vpn_users.email`), Telegram ID (уникален). |
| Что выдаётся | Приглашение несёт протокол (обычный AmneziaWG сервера или шлюз) и срок в днях; значения по умолчанию — в настройках бота. |
| Конфиг | Ссылка на страницу панели `/c/<токен>`, а не файл в чат: файл в Telegram остаётся навсегда вместе с приватным ключом. |
| Рассылки и уведомления | Исходящая очередь (outbox) в БД панели; бот забирает и отправляет сам. |
| Язык бота | Только русский. Тексты бота — в одном модуле, чтобы позже добавить en. |
| Оплата | Не делается; в процессе регистрации есть шаг «оплата», который сейчас всегда пройден (6.3). |

## 3. Архитектура

```
Telegram  ⇄  бот (aiogram 3, long polling)  ── HTTPS, X-Bot-Key ──►  API панели  ──►  БД, воркер, SSH
                                                                       ▲
                                     пользователь открывает /c/<токен> ┘  (страница панели)
```

- **Код бота** — каталог `bot/` в этом репозитории: свой `pyproject.toml`, свой `Dockerfile`, свой
  `docker-compose.yml` (для варианта 3). Бот **не импортирует** `src/` — только HTTP-клиент к API панели
  (правило проверяется тестом, как «`infrastructure/` не импортирует `modules/`»).
- **Модуль панели** — `src/modules/bot/`: модели, Bot API (`/api/v1/bot/*`), админский API (`/api/v1/bot-admin/*`),
  публичная страница конфига (`/api/v1/public/config/{token}`).
- **Опрос**: бот ходит в панель каждые 5 с за очередью и раз в 30 с — heartbeat. Панель видит «последний опрос»
  и показывает его на странице «Бот».
- **Адрес панели** для бота: вариант 1 — `http://api:8000` внутри compose; вариант 3 — `https://<домен панели>`
  с проверкой TLS (для своего сертификата — `PANEL_CA_FILE`).

## 4. Модели (панель)

Имена ориентировочные, финальные — за architect в 25.1.

- **`vpn_users`**: + `telegram_id` (BIGINT, UNIQUE, NULL — пользователи, созданные админом или импортом),
  + `telegram_username` (для отображения, может меняться), + `bot_blocked_at` (пользователь заблокировал бота —
  исключается из рассылок).
- **`bot_keys`**: `key_hash` (SHA-256), `name`, `created_by` (админ), `created_at`, `last_seen_at`,
  `last_seen_version`, `bot_username` (сообщает бот), `revoked_at`. Ключ показывается один раз при создании.
- **`bot_settings`** (одна строка): `default_protocol_id`, `default_days`, `notify_events` (список типов событий),
  `panel_down_after_seconds` (по умолчанию 300).
- **`bot_invites`**: `code_hash`, `protocol_id`, `days`, `expires_at`, `note` (кому), `created_by`, `used_at`,
  `used_by_user_id`, `revoked_at`. Одноразовое.
- **`bot_registrations`**: `telegram_id`, `invite_id`, `name`, `email`, `status`
  (`collected` → `payment_pending` → `provisioning` → `active` | `failed`), `user_id`, `error`, таймстемпы.
  Одна незавершённая регистрация на `telegram_id`.
- **`config_links`**: `token_hash`, `credential_id`, `created_at`, `revoked_at`, `last_opened_at`. Действует, пока
  доступ живой; отзыв/истечение доступа отзывает ссылку.
- **`bot_outbox`**: `kind` (`broadcast` | `config` | `notify`), `telegram_id`, `text`, `broadcast_id`,
  `status` (`pending` | `claimed` | `sent` | `blocked` | `failed`), `claimed_until`, `attempts`, `error`,
  таймстемпы. Доставка «не меньше одного раза»: взятое ботом и не подтверждённое за `claimed_until` возвращается.
- **`bot_broadcasts`**: `text`, `target` (все / выбранные / по протоколу), `created_by`, счётчики
  `total/sent/blocked/failed`.
- **`admin_telegram_links`**: `admin_id`, `telegram_id`, `linked_at` — куда слать уведомления админу.

Секреты (ключ бота, код приглашения, токен ссылки) — в БД только хешем. Аудит — у каждого действия админа и у
регистрации; в аудит не попадают коды, токены, почта целиком не нужна (id пользователя).

## 5. Bot API (`/api/v1/bot/*`, заголовок `X-Bot-Key`)

Отдельная зависимость авторизации (не JWT админа), свой rate limit. Ключ не даёт доступа к админскому API.

| Метод | Что |
|---|---|
| `POST /heartbeat` | `{bot_username, version}` → `{settings_version}`; обновляет `last_seen_at` |
| `POST /invites/check` | `{code}` → годно / использовано / истекло / нет такого (без деталей приглашения) |
| `POST /registrations` | `{code, telegram_id, telegram_username, name, email}` → `{registration_id, status}`; 409 — почта или Telegram заняты, приглашение использовано |
| `GET /registrations/{id}` | статус; при `active` — URL страницы конфига |
| `GET /users/by-telegram/{telegram_id}` | `/status`: имя, до какого числа доступ, протокол |
| `POST /users/by-telegram/{telegram_id}/config-link` | `/config`: новая ссылка, прежняя отзывается |
| `POST /outbox/claim` | `{limit}` → пачка сообщений (`claimed_until` = сейчас + 60 с) |
| `POST /outbox/ack` | `[{id, status: sent|blocked|failed, error?}]`; `blocked` ставит `bot_blocked_at` пользователю |
| `POST /admin-links` | `{code, telegram_id}` — привязка Telegram админа одноразовым кодом из панели |

## 6. Регистрация

### 6.1 Диалог бота

1. `/start <код>` → `invites/check`. Не годно — понятный текст, конец. Без кода — «закрытое тестирование».
2. Уже зарегистрирован этот Telegram → «вы уже зарегистрированы», подсказка `/config`, `/status`.
3. «Как вас зовут?» → имя (1–64 символа, без управляющих).
4. «Ваша почта?» → почта (проверка формата в боте, окончательная — в панели).
5. Подтверждение «Имя, почта — верно?» [Да] [Изменить].
6. `POST /registrations` → «Готовим доступ…»; бот опрашивает статус (до 3 мин).
7. `active` → «Готово» + ссылка на страницу конфига + короткая инструкция. `failed` → «не получилось, админ уже
   знает» (+ уведомление админу).

### 6.2 Что делает панель

`collected` → шаг оплаты (6.3) → `provisioning`: пользователь (имя, почта, `telegram_id`), подписка на `days`
приглашения, доступ к протоколу приглашения — **существующими сервисами** `vpn_users`/`access` (задача воркера на
сервере, как при выдаче из панели) → `active`: ссылка на конфиг, приглашение помечено использованным. Ошибка
SSH/задачи — `failed` с текстом без секретов; админ видит регистрацию в панели и может повторить.

### 6.3 Место для оплаты (не реализуется)

Шаг `payment_pending` вызывает `PaymentPolicy`. Сейчас одна реализация — `InviteFree`: всегда «оплачено», шаг
проходит сразу. Позже: политика по приглашению/тарифу, бот показывает кнопку оплаты, подтверждение провайдера
переводит регистрацию в `provisioning`. Остальные шаги не меняются.

## 7. Страница конфига `/c/<токен>`

- Публичный маршрут фронтенда вне авторизации + `GET /api/v1/public/config/{token}`.
- Показывает: имя пользователя, до какого числа доступ, ссылку `vpn://` (кнопка «Скопировать»), серию QR,
  скачивание `.conf`, инструкции (Android, iOS, Windows, macOS: «установите AmneziaVPN → импорт»).
- Безопасность: токен ≥ 32 байт случайных, в БД хеш; rate limit по IP; `Cache-Control: no-store`,
  `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`; неверный, отозванный и истёкший токен — одинаковый 404.
  Открытие пишет `last_opened_at` (без IP в аудит).
- У импортированных из AmneziaVPN клиентов приватного ключа нет — ссылку на них не выдавать (409 в API).

## 8. Панель: страница «Бот»

Видна, если есть хотя бы один ключ бота. Права — новые: `bot:read` (viewer+), `bot:manage` (operator+),
`bot:keys` (superadmin) — строки в RBAC-матрице.

- **Состояние**: бот `@имя`, последний опрос (давно > 2 мин — предупреждение), версия; ключи (создать — показать
  один раз, отозвать).
- **Приглашения**: создать (протокол, срок, «действует до», заметка «кому») → ссылка `t.me/...` с копированием;
  список с состоянием (ждёт / использовано кем / истекло / отозвано); отозвать.
- **Регистрации**: список, `failed` — текст ошибки и «Повторить».
- **Рассылка новостей**: текст (Telegram HTML, предпросмотр), кому: все / выбранные / по протоколу; прогресс
  (отправлено / заблокировали / ошибки).
- **Рассылка конфигов**: индивидуально (из карточки пользователя: «Отправить ссылку в Telegram») и массово
  (выбранным / по протоколу) — каждому новая ссылка на его конфиг.
- **Уведомления админу**: привязать свой Telegram (одноразовый код → боту `/admin <код>`), галочки событий.
- **Настройки**: протокол и срок по умолчанию, порог «панель недоступна».

## 9. Уведомления админу

- **События панели** → строки `bot_outbox` (`kind=notify`) каждому привязанному админу. Источник — события аудита
  с курсором (чтобы не терять и не дублировать): `gateway_all_exits_down`, `gateway_failover`,
  `gateway_exit_recovered`, события `*_failed` задач, `failed`-регистрация. Список — в `notify_events`.
- **Новое событие аудита `server_health_changed`** (`server_id`, `from`, `to`): сейчас `servers/health.py` только
  перезаписывает `health_status`, события о переходе нет. Писать только при смене статуса (ok/degraded → down,
  down → ok), не на каждой проверке. Делается в 25.5.
- **Панель недоступна** — решает бот: нет успешного ответа API дольше `panel_down_after_seconds` → сообщение всем
  привязанным админам (список chat id бот хранит локально и обновляет при heartbeat); восстановление — второе
  сообщение. При варианте 1 (бот на том же сервере) падение самого хоста не обнаружить — это видно в настройках.
- Повторы: одно событие — одно сообщение; «панель недоступна» — не чаще раза в 30 мин, пока не восстановится.

## 10. Установка

- **`install.sh`**: вопрос после админа:
  `Telegram-бот: 1) на этом сервере  2) на другом сервере (выдам команду)  3) не нужен [3]`.
  - 1 → токен от @BotFather (проверка `getMe` — с этого сервера может не пройти: тогда предупредить и предложить
    вариант 2), создать ключ бота, записать в `.env.prod` `COMPOSE_PROFILES=bot` и переменные бота.
  - 2 → создать ключ бота, напечатать команду для другого сервера (`git clone … && ./bot/install-bot.sh`) с адресом
    панели; ключ — один раз на экран.
- **`bot/install-bot.sh`** (вариант 3): Docker, вопросы: адрес панели, ключ бота, токен Telegram; проверка
  `getMe` и `/heartbeat`; `bot/.env` (0600); `docker compose up -d`.
- **`./panel bot enable|disable|key`** — включить/выключить бота на сервере панели и выпустить новый ключ без
  переустановки.
- Тесты — как у установщика сейчас (`tests/unit/test_install_*.py`, заглушки Docker и curl).

## 11. Безопасность (сводно)

- Ключ бота, коды приглашений, токены ссылок — только хешем; ключ и код показываются один раз.
- Ключ бота — узкая роль: только Bot API; отзыв ключа немедленно отключает бота.
- Токен Telegram в панели не хранится.
- Ни ключей VPN, ни конфигов в сообщениях Telegram и логах бота — только ссылка.
- Ввод из Telegram — недоверенный: длины, управляющие символы, почта через `EmailStr`; в SSH-команды не попадает
  (как и любой ввод сейчас).
- Rate limit: Bot API — по ключу; страница конфига — по IP; регистрации — не больше N в минуту на ключ.

## 13. Вне рамок сейчас

Оплата и тарифы; английский язык бота; несколько ботов на одну панель (модель ключей это допускает, UI — нет);
самостоятельная смена почты пользователем; удаление аккаунта из бота (делает админ).
