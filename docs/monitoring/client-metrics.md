# Текущая статистика VPN-клиентов

В карточке пользователя у действующего VPN-устройства показываются последнее рукопожатие,
скачанные и отправленные байты. Направления относятся к клиенту: скачано — TX сервера,
отправлено — RX сервера. Данные доступны администратору с `servers:read`.

Это текущие счётчики интерфейса, а не накопительный учёт в панели. Они могут обнулиться при
перезапуске VPN или пересоздании peer'а; начало периода неизвестно. Подпись — «Трафик со стороны
клиента с последнего сброса VPN». История и сумма за всё время не сохраняются, миграции БД нет.

## Сбор и хранение

Существующий `MetricsCollector` раз в 60 секунд вызывает `VPNProvider.client_stats()` для
каждого протокола сервера. Обычный AWG и шлюз используют свой `ContainerLayout`, APP AWG/AWG2 —
собственные контейнер, инструмент и интерфейс. Проверки принадлежности контейнера сохраняются.
Существующий `client_counts()` продолжает отдельно считать сводные показатели сервера.

Команды читают только `show <interface> latest-handshakes` и `show <interface> transfer`.
Фрагменты команд заданы провайдером, пользовательский ввод не подставляется. `dump` запрещён:
он содержит приватные ключи. Конфиг не читается для получения этой статистики.

`VPNClientStats` содержит публичный ключ, `latest_handshake`, `rx_bytes`, `tx_bytes`.
Результат `None` означает недоступный замер, `[]` — успешный замер без peer'ов.
При успешном чтении handshake и ненулевом коде `transfer` время сохраняется, байты равны `null`.
Неверные ключи, отрицательные/битые счётчики и превышение границ разбора отбрасываются.

Снимок хранится атомарно в Redis под ключом `client_metrics:<protocol_id>` с TTL 86400 секунд:
`sampled_at` и список `peers`. Сбой SSH не затирает предыдущий успешный снимок. Содержимое вывода
команд и секреты в журнал не записываются. Недоступный Redis не должен ронять чтение статистики.

## API

`GET /api/v1/servers/{server_id}/clients/monitoring` требует входа и `servers:read`.
GET читает только БД/Redis, не запускает SSH или сбор. Неизвестный сервер — 404,
невалидный UUID — 422, отсутствие входа — 401, отсутствие права — 403.

Ответ `ServerClientMetrics` содержит:

- `server_id`;
- `protocols[]`: `protocol_id`, `sampled_at`, `stale`, `clients[]`;
- `clients[]`: `credential_id`, `latest_handshake`, `downloaded_bytes`, `uploaded_bytes`.

Peer сопоставляется только с неотозванным credential того же сервера и протокола по публичному
ключу. Имя не используется. Неизвестные и внутренние peer'ы без такого credential не выдаются;
публичный ключ и конфиги в ответ не входят.

При отсутствии, повреждении или истечении срока снимка: `sampled_at: null`, `stale: false`,
`clients: []`. Возраст не менее 300 секунд или время замера из будущего дают `stale: true`.
Отозванный credential не появляется даже в сохранённом старом снимке.

## Интерфейс

`ClientMetrics.tsx` использует общий query key сервера, опрос каждые 60 секунд.
Текущее время в интерфейсе обновляется каждые 30 секунд независимо от запросов, включая офлайн;
от него считаются относительное время и устаревание. Точная дата — в подсказке `<time>`.
Нет снимка или нет соответствующего устройства — «Статистика устройства пока недоступна».
Неизвестные байты — «—», известный нулевой счётчик — «0 Б».

«Ещё не подключался» допустимо только для свежего успешного замера без handshake. Для старых данных
выводится предупреждение «Данные устарели»; отсутствие handshake в них показывается как «—».
При ошибке обновления уже загруженный снимок остаётся видимым с предупреждением.

## Проверки

- `tests/unit/test_client_stats.py`: формат/границы счётчиков, проверки контейнеров, AWG/gateway/APP,
  отсутствие чтения конфигов, недоступность и частичные данные.
- `tests/services/test_client_metrics.py`: направления трафика, TTL/свежесть, повреждённый Redis,
  отозванные credentials и разделение серверов.
- `tests/integration/test_client_metrics_api.py`, `test_rbac.py`: cache-only GET, вход, права, 404/422.
- `frontend/src/pages/user/ClientMetrics.test.tsx`: время, направления, нули/нет данных,
  устаревание, общий запрос и переводы.

Живая проверка на VPN-сервере выполняется только с явного согласия. Проверять чтение, направления
байтов и отображение свежести без отзыва peer'ов, перезапуска VPN и раскрытия конфигов.
