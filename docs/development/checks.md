# Компактные результаты проверок

`scripts/check.py` запускает явно указанную команду, сохраняет stdout/stderr в локальный
приватный `.checks/*.log` и выводит только PASS/FAIL, длительность и путь к логу.
Код завершения команды сохраняется; ошибка запуска даёт 127, прерывание — 130.

Из корня репозитория:

```bash
python scripts/check.py backend-unit -- uv run pytest tests/unit/test_release_deploy.py -q --tb=short
python scripts/check.py backend-types -- uv run mypy src
```

Команда получает текущий рабочий каталог и окружение. Для отдельного пакета бота запускайте
проверку из `bot/`, чтобы `uv` выбрал его проект:

```bash
cd bot
python ../scripts/check.py bot-tests -- uv run pytest -q --tb=short
```

Аргументы передаются процессу без shell. Операторы `&&`, `|` и перенаправления не обрабатываются:
запускайте отдельные проверки отдельными командами. В Windows указывайте исполняемую команду,
например `npm.cmd`, если нужный инструмент представлен npm-обёрткой.

Обёртка не выбирает тесты, не кеширует их результат и не пропускает повторные запуски.
Используйте адресные тесты после изменения; полный прогон — когда его требуют затронутые
механизмы и инструкции проекта. После новых правок прежний результат не подтверждает
изменённый участок: повторите соответствующие проверки.

При FAIL прочитайте нужный участок указанного лога. В рабочий контекст переносите причину,
затронутый тест и существенный фрагмент ошибки, а не весь файл. Лог содержит исходный вывод
команды без фильтрации секретов; не запускайте через обёртку команды, раскрывающие ключи,
токены или конфиги, и не публикуйте логи целиком. `.checks/` исключён из Git; очистка ручная.

Для передачи задачи достаточно цели, изменённых файлов, принятых решений, проверок для
текущей версии кода и следующего шага. Отдельно укажите ограничения проверки. Подробные
логи и историю команд оставляйте по локальным путям; успешные проверки повторяйте после
новых изменений или новой находки, влияющей на их результат.
