# frontend — подробное устройство (страницы, разделы, хелперы)

Полная таблица из `frontend/CLAUDE.md`, перенесена без изменений текста; там осталась короткая карта.

## Устройство

| Путь | Что |
|---|---|
| `src/i18n/` | i18next + react-i18next, два языка: ru и en. Язык — из `localStorage` (`vpn-panel-lang`), иначе по браузеру (русский → ru, остальное → en). `format.ts` — текущий язык и кеш `Intl`-форматтеров. Смена языка пересоздаёт роутер (`LocalizedRouter` в `main.tsx`), поэтому даты и числа обновляются сразу. |
| `src/locales/{ru,en}/` | Словари по разделам: `common`, `shell`, `auth`, `jobs` (типы и статусы задач — общие), `servers`, `users`, `audit`. Ключи по смыслу: `t("shell.nav.servers")`. Типы ключей берутся из ru — опечатка ломает `tsc`. Вне компонентов — `i18n.t(...)` из `src/i18n`. |
| `src/api/client.ts` | `api` (openapi-fetch, `baseUrl = window.location.origin`), `unwrap()`, тип `Schemas`. `ApiError.detail` — текст `detail` ответа (английский, для выбора сообщения, показывать нельзя). |
| `src/api/schema.d.ts` | Генерируется: `PYTHONPATH=src uv run python -m scripts.export_openapi frontend/openapi.json` (из корня) → `npm run gen:api`. Руками не править. |
| `src/api/session.ts` | Access-токен **только в памяти**; `authFetch`: 401 → один общий refresh (single-flight) → повтор. |
| `src/auth/AuthContext.tsx` | Состояния checking/signed-out/signed-in, `can(permission)` — по `permissions` из `/auth/me`; `changePassword` (свой `fetch`, чтобы после 401 обновить токен и повторить; потом перечитывает профиль). |
| `src/auth/RequireAuth.tsx` | Пускает только вошедшего; с `must_change_password` вместо панели — `ChangePasswordPage` на том же адресе (бэкенд для такого админа отвечает 403 на всё, кроме `/auth/me`, смены пароля, refresh и logout). |
| `src/App.tsx` | Маршруты: `/login`, `/servers`, `/servers/:serverId`, `/users`, `/users/:userId`, `/audit` — каждый раздел грузится отдельным чанком (`lazy`), в основном бандле каркас, вход и словари. |
| `src/pages/server/` | Карточка сервера: правка имени и заметки (`EditServerDialog`; адрес не меняется — его смена сбрасывает ключ и доступ), чек-лист подготовки (ключ хоста, учётка, установка, протокол), обслуживание (учётка, ключ панели), мониторинг (ленивый чанк), журнал задач, опасные действия; ссылка «События сервера» (при `audit:read`) открывает журнал по серверу. **Установленная AmneziaVPN**: `useServerData` читает `GET /discovery` (ключ `keys.discovery`, только при SSH-учётке; сбой отчёта молча прячет блок); найденное приложение — блок `AmneziaAppSection` («На сервере уже есть AmneziaVPN»: контейнер, порт, состояние, клиентов/новых) и при `servers:manage` кнопка «Подхватить клиентов» → `ImportClientsDialog`; «Найти существующую Amnezia» (`POST /discover`, `servers:check`) — в «Обслуживании» и в шаге протокола. Контейнер v1 (`amnezia_app_awg`) занимает имя панельного — шаг «Установить AmneziaWG» вместо кнопки показывает подсказку, для `awg2` — предупреждение. Найденное приложение открывает «Обслуживание» (проверка, сверка, поиск) и без протокола в панели — чек-лист при этом остаётся для шага протокола. «Свой» протокол — только `amnezia_wg`: «Снять AmneziaWG» и порт в «Обслуживании» относятся к нему; строка протокола приложения (появляется после переноса) считается «протокол есть». **Шлюз** (`amnezia_gateway`) — отдельный протокол со своим контейнером: в `protocol` он не попадает (`protocol = amnezia_wg ?? любой, кроме шлюза`), шаг «протокол» чек-листа по одному шлюзу не выполнен, но шлюз доказывает установку Amnezia и открывает «Обслуживание». Ставится кнопкой «Установить шлюз» рядом с обычным протоколом (шаг чек-листа и строка «Шлюз» в «Обслуживании»: `ServerAction` `gateway-install` — `POST /protocol` с телом `{type}`), снимается в «Опасных действиях» (`gateway-remove` — `DELETE /protocol?type=amnezia_gateway`); задача `install_protocol` общая, поэтому подпись задачи — «Установка протокола». Сервер со шлюзом показывает раздел `GatewaySection` (см. ниже). |
| `src/pages/server/gateway/` | Раздел «Шлюз» карточки сервера (`GatewaySection`, только при протоколе `amnezia_gateway`). **Сводка**: подсеть клиентов (`GATEWAY_SUBNET` = `10.77.0.0/22`, зашита в провайдере бэкенда), порт, контейнер (проверка `container` из отчёта последней `health_check` в журнале задач — отдельного API нет), исправные выходы, клиенты с выходом и без. **Выходы** (`ExitsPanel`): таблица (на 375px строки становятся блоками «подпись — значение»), состояние `exitView`: «Подключается»/«Снимается» только пока идёт задача `gateway_add_exit`/`gateway_remove_exit`, иначе упавшая операция — «Не подключился» (кнопка «Повторить» = тот же POST) / «Не снят»; «Ошибка» — health `down`/`stale` (их балансировщик считает отказом), `no_handshake` — только жёлтая полоса. Кнопки при `servers:manage`: «Добавить выход» (`AddExitDialog`: серверы панели с `amnezia_wg`, кроме шлюза и уже подключённых; вес 1..100, лимит `1..100000` или пусто → `null`; проверки до запроса), «Изменить» (`PATCH`, пустой лимит снимает предел), «Снять» (`ConfirmDialog`: 409 с числом клиентов — `ApiError.detail` разбирает `clientsLeft` — бросает `NeedsConfirmation`, диалог остаётся открытым и предлагает «Снять всё равно» = `?force=true`; другой 409 — обычный текст). **Клиенты и выходы** (`AssignmentsPanel`): имя клиента собирает `useGatewayClients` цепочкой «пользователи → подписка → доступы → конфиги» теми же ключами, что карточка пользователя (в API назначений есть только `credential_id`, обратного поиска нет; нужны `access:read` и `vpn_users:read`, иначе «Клиент c1c1c1c1»); живые клиенты шлюза без назначения показываются первыми как «нет выхода» (статуса «без выхода» бэкенд не ведёт); перенос/закрепление (`MoveClientDialog`, быстрые «Закрепить»/«Открепить»; `access:manage`; 502 = «не применилось на шлюзе, ничего не изменилось»), «Проверить сейчас» (`servers:check`), по 25 строк. **«Россия напрямую»** (`RuPanel`): активный список (версия, диапазоны, дата), «Обновить из RIPE» (глобальная задача без сервера — следим за ней через `useJob`, в журнал сервера она не попадает), «Загрузить файл» (`UploadListDialog`: файл читается в браузере, до 5 МБ, тело `text/plain` — в схеме у маршрута тела нет, поэтому `bodySerializer`), кандидат на подтверждение (`activate`), исключения (`AddOverrideDialog`, CIDR проверяется по виду, остальное — бэкенд), «Применить на шлюзе» (недоступно без активного списка; итог последнего применения — из журнала задач). Отказы бэкенда (английские фразы `detail`) переводит `geoipErrorText`, незнакомую фразу пользователю не показываем. Данные: `keys.gateway*`/`geoipKeys` (`useServer.ts`); завершение любой задачи сервера сбрасывает префикс `keys.gateway(id)` и `geoipKeys.all`; выходы и назначения перечитываются раз в 30 с. Стили — `Gateway.module.css` (composes из `ServerPage.module.css`). |
| `src/pages/server/ImportClientsDialog.tsx` | Перенос клиентов: выбор установки (если найдено две), срок «Доступ действует до» (по умолчанию +30 дней, от завтра до +10 лет, формат проверяет `isValidDay`; уходит как конец дня по местному времени в ISO), список клиентов (новые выбраны; `in_panel`/`unsupported` недоступны с пояснением; `revoked_in_panel` доступен, не выбран; имя по умолчанию — имя из приложения без управляющих знаков или «Client N», email необязателен и без повторов), проверки до запроса (`noValidate`, `TextField error`; сводка «Есть ошибки в полях: N» и фокус на первом поле с `aria-invalid`; длина имён — в кодовых точках; не больше 250 выбранных — начальный выбор и «Выбрать все новые» режутся по лимиту; поля строки сгруппированы `role=group`, названной адресом; ответ 422 с `loc` вида `clients.N.email|username` подсвечивает строку), затем итог из `job.result`: задача берётся из общего запроса `keys.jobs` (`fetchJobs`, один опрос с журналом задач, без отдельного `GET /jobs/{id}`) (счётчики + причины конфликтов; известные английские причины бэкенда переводятся в `discovery.ts`). Состояние формы живёт, пока диалог открыт. Хелперы — `discovery.ts` (`isImportable`, `importSummary`, `conflictReason`); итог переноса также строкой в `JobsLog`. |
| `src/pages/user/` | Карточка пользователя: правка имени, email и заметки (`EditUserDialog`), подписка, «Выдать доступ» (подписка → гранты → задачи выдачи), срок, отзыв, конфиг (vpn:// + серия QR + .conf). `email` может быть `null` (подхвачены из AmneziaVPN): в списке и карточке «—», в `EditUserDialog` поле необязательно, пустое не отправляется. Credential с `source: "imported"` (`GrantRow`): кнопки «Показать конфиг» нет (приватного ключа у панели нет, `/config` → 409), вместо неё пометка; «Выдать конфиг» для доступа, у которого есть подхваченный клиент (даже отозванный), не показывается — клиентов приложения создаёт только оно. `GrantAccessDialog` предлагает протоколы `amnezia_wg` и `amnezia_gateway` (не первый в списке и не протокол приложения); пункт — это протокол сервера, а не сам сервер: у шлюза рядом с именем метка «Шлюз», уже выданное скрывается по `protocol_id`, поэтому AmneziaWG и шлюз одного сервера выдаются отдельно. `GrantRow` для доступа к шлюзу помечает сервер «Шлюз» (тип протокола — из `keys.protocols`, нужно `servers:read`) и `GatewayExitNote` показывает выход клиента («Идёт через выход 2 — Frankfurt» или «Выход не назначен — интернета нет») из `gateway/assignments`; конфиг, QR и ссылка — как у обычного доступа. |
| `src/pages/AuditPage.tsx` | Журнал `/audit`: фильтры в URL (`admin_id`, `group`, `entity_type`, `entity_id`, `from`, `to`); подгрузка `useInfiniteQuery` по 100, курсор — `before_created_at`/`before_id` последней строки. Имена объектов — из уже загруженных списков серверов и пользователей (без права на список объект не называется). |
| `src/pages/Ledger.module.css` | Общие стили таблиц-журналов. |
| `src/pages/ChangePasswordPage.tsx` | Экран временного пароля «Задайте свой пароль» (форма + «Выйти»). Форма — `components/ChangePasswordForm` (проверки длины, совпадения и «не равен текущему» до запроса; `noValidate`, сообщения свои). «Сменить пароль» в блоке учётки — `ChangePasswordDialog`. |
| `src/components/` | Button, Dialog (`wide` — широкое окно для списков), ConfirmDialog (с последствиями; `onConfirm(again)` может бросить `NeedsConfirmation` — диалог останется открытым с текстом и новой кнопкой, повтор придёт с `again = true`), TextField (`error` — сообщение под полем, `aria-invalid`), Notice, AppShell, ThemeSwitch, TimeChart (uPlot), ChangePasswordForm/-Dialog. |
| `src/lib/` | `access.ts` (сигнал доступа по датам), `serverSignal.ts`, `jobs.ts`, `time.ts`, `units.ts`, `theme.ts`; `audit.ts` — группа и важность событий (`AUDIT_ACTIONS`), текст события — в словаре `audit.actions.<action>` (`auditActionText`), группы — стабильные идентификаторы (`signIn`, `admins`, `servers`, `access`, `configs`, `gateway`: они в адресе `?group=servers`; в `gateway` — все события шлюза и «России напрямую»), `actionGroups`/`actionsOfGroup` для фильтра, `auditActor`, `auditSubject`, `auditDetails` (белый список `DETAIL_KEYS`: для поиска/переноса AmneziaVPN — только счётчики `protocols`, `clients`, `imported`, `already`, `gone`, `unsupported`, `conflict`, а также `public_key` и `source`; для шлюза — слоты (`slot`, `from_slot`, `to_slot`), счётчики (`moved`, `unassigned`, `routes`, `count`, `exits`), `version`, `sha256`, `network`, `weight`, `protocol_type`, `action`, `status`, `force`, `reason`; слова бэкенда из `TRANSLATED_VALUES` переводятся словарём `audit.values.*`, `reason` — только у событий `gateway_*`; id объектов, в том числе `exit_id`, `credential_id`, не показываются). `time.ts` — ещё `localDay`, `addDays`, `endOfLocalDay` (дата из `<input type="date">` → конец дня по местному времени). |
| `src/styles/tokens.css` | Дизайн-токены (светлая и тёмная тема). |
