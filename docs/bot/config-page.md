# modules/bot — страница конфига: ссылка, открытие, безопасность

Инварианты — в `src/modules/bot/CLAUDE.md`. Здесь — формат ссылки, жизненный цикл, проверки при открытии и ответы.
Маршруты и коды — `docs/bot/api.md`; страница в браузере — `docs/frontend/structure.md`.

## Ссылка

- Адрес: `<публичный адрес панели>/c#<токен>`. Токен — `generate_token(32)`: 43 символа `[A-Za-z0-9_-]`.
- Токен во фрагменте (после `#`): браузер не отправляет его на сервер. Он не попадает в логи nginx и API, в `Referer`,
  и превью Telegram не открывает страницу.
- Публичный адрес: `PUBLIC_URL`; если пуст — `https://PANEL_DOMAIN`, с `:HTTPS_PORT`, если порт не 443. Пусто и то и
  другое — ссылок нет (409 `not_configured`).
- Бот адрес не собирает: берёт `config_url` из ответа `POST /api/v1/bot/users/by-telegram/{id}/config-link`.
- В БД — только SHA-256 токена (`token_hash`).

## Жизненный цикл

| Событие | Что с ссылкой |
|---|---|
| `config-link` (бот: `active`, `/config`, повтор после сбоя отправки) | выпускается новый токен; живая ссылка этого клиента получает `revoked_at`; токен виден только в ответе |
| Человек открывает ссылку | конфиг по проверкам ниже, `last_opened_at`. Ссылка не одноразовая |
| Доступ закончился; клиент, грант или подписка отозваны | открытие → 404; строка остаётся, `revoked_at` не ставится |
| Клиент удалён | строка ссылки удаляется каскадом |
| Downgrade миграции `b4f1c8e27a69` | все ссылки теряются: людям нужно снова написать `/config` |

## Какой клиент получает ссылку

Кандидаты — неотозванные клиенты человека с живым доступом (`inactive_reason` по гранту и подписке).

1. Адрес не задан → 409 `not_configured` (проверяется первой, до поиска человека).
2. Нет человека с таким `telegram_id` → 404.
3. Среди кандидатов есть клиент, выданный панелью (с конфигом): клиент гранта регистрации через бота, если он среди них;
   иначе самый новый.
4. Есть только импортированные из AmneziaVPN → 409 `config_unavailable`.
5. Живой доступ есть, но по его гранту идёт `CREATE_USER` → 409 `not_ready`.
6. Иначе → 409 `no_access`.

Выпуск — одна транзакция: клиент блокируется (`FOR UPDATE`), живая ссылка клиента отзывается, вставляется новая, пишется
аудит, commit. Два одновременных выпуска идут по очереди за блокировкой клиента. Частичный уникальный индекс — страховка:
при его срабатывании повтор один раз, второй конфликт → 409 `no_access`. Отказы не создают строк и не пишут аудит.

## Проверка при каждом открытии

`POST /api/v1/public/config` с телом `{"token": "<токен>"}`:

1. Формат: 43 символа `[A-Za-z0-9_-]`. Иначе — 404, до БД.
2. Лимит неудач по IP — до БД.
3. Поиск по хешу токена: ссылка не отозвана; клиент не отозван, выдан панелью и с конфигом.
4. `inactive_reason(grant, subscription, now)`: статусы гранта и подписки, даты (`valid_until`). Без планировщика.
5. Расшифровка и форматы (`render_config`) — только после шагов 1–4.
6. `last_opened_at`, ответ.

Ответ 200 — `PublicConfigRead`: `name` (имя человека), `valid_until` (конец подписки), `server_name`, `config` (.conf
целиком), `share_link` (`vpn://…`) и `share_qr` (серия строк) — либо `null`, если приложение не собрало формат (тогда
остаётся `.conf`); `file_name` — ASCII `[A-Za-z0-9_-]`, до 40 символов, по умолчанию `amnezia`.

## Ответы

| Ответ | Когда |
|---|---|
| 200 | ссылка действует |
| 404 `{"detail": "Not found"}` | любой отказ: токен неверного вида, неизвестен, заменён или отозван; клиент, грант или подписка не действуют; срок вышел; клиент импортирован |
| 422 | тело не разобрано или `token` длиннее 256 символов; срабатывает до обработчика, в лимиты не попадает |
| 429 с `Retry-After` | превышен лимит по IP |

Все отказы при открытии дают один и тот же 404, побайтно. Ответы 200 и 404 несут `Cache-Control: no-store` и
`X-Robots-Tag: noindex, nofollow`; `Set-Cookie` не ставится. nginx ставит `X-Robots-Tag` на весь сайт; на `/api/` его
отдаёт сам API, nginx его не дублирует.

## Лимиты по IP

- Неудачи — `PUBLIC_CONFIG_IP_MAX_FAILURES` (по умолчанию 20) за `PUBLIC_CONFIG_IP_FAILURE_WINDOW_SECONDS` (600 с).
  Неудача — 404 на открытие. Проверка до БД, запись — при отказе. Открытия не считаются: за общим адресом (CGNAT)
  успешные открытия никого не блокируют.
- Запросы — `PUBLIC_CONFIG_IP_MAX_REQUESTS` (60) за `PUBLIC_CONFIG_IP_REQUEST_WINDOW_SECONDS` (60 с). Считается каждый
  запрос, дошедший до обработчика.
- Адрес клиента — тот же, что у остальных лимитов (`get_request_ip`). Без адреса — общая корзина `unknown`.
- Redis недоступен — лимиты не действуют (fail-open, `src/core/CLAUDE.md`).

## Страница в браузере

- Маршрут `/c` вне входа: `AuthProvider` не поднимается, `POST /auth/refresh` не вызывается.
- Токен берётся из `location.hash` и уходит только в теле POST (`credentials: "omit"`, `cache: "no-store"`).
- Адрес страницы не меняется: токен остаётся в адресной строке и истории браузера.
- Конфиг живёт только в состоянии страницы. При `pagehide` убирается, вместо него — «Конфиг убран с экрана».
- Заголовок документа — без имени и токена.
- Тексты ошибок: 404 и 422 — «ссылка недействительна» (один текст на все случаи), 429 — «слишком много попыток», сеть —
  «нет связи», прочее — «страница не открылась».

## Безопасность

- Ссылка — секрет: кто её открыл, видит конфиг. Потеря или пересылка — повод написать `/config`.
- Токен — 32 байта случайных данных. 404 не показывает, существовал ли токен.
- В аудит не пишется открытие страницы; `last_opened_at` — единственный след. Выпуск — `config_link_created` с
  `{credential_id, user_id, source: "bot", replaced}`, без токена и хеша.
- Логи панели: поле `token` маскируется (`core/log.py`).
- Логи бота: адрес `…/c#…` маскируется целиком (`bot/src/tollwire_bot/log.py`); `ConfigLink.__repr__` адрес не
  показывает; превью ссылок выключено (`link_preview_is_disabled`).
- Токен возвращается только в ответе `config-link`; повторно его получить нельзя, список ссылок не показывает токены.

## Компромиссы

- Токен в адресной строке и истории браузера. На общем компьютере тот, кто видит историю, видит и конфиг, пока ссылка
  жива.
- Лимит неудач по IP считает адрес целиком, для IPv6 — не `/64`.
- Отозванные и просроченные строки `config_links` не удаляются: чистки нет.
- Ссылка, которую бот не смог отправить, гаснет при следующем выпуске. Токен, не дошедший до человека, мёртв и никуда
  не утёк.
