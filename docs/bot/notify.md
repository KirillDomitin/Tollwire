# Уведомления администратору: серверные сервисы

Серверные сервисы, HTTP, Telegram-бот и интерфейс. HTTP-контракт — [api.md](api.md), наблюдение за панелью —
[panel-watch.md](../bot-service/panel-watch.md).

## Привязка

`AdminLinkService` и `AdminLinkRepository` управляют `admin_telegram_links`. Один администратор —
одна строка, один Telegram — не более одного администратора. Операции блокируют сначала
администратора, затем привязку; уникальное ограничение разрешает гонку за один Telegram.

- `issue_code`: 32 URL-безопасных символа, в БД только SHA-256, срок
  `BOT_ADMIN_LINK_CODE_TTL_SECONDS` (600 с). Новый код заменяет старый, сохраняя текущий Telegram.
- `link`: активный администратор, действующий одноразовый код; причины отказа `link_invalid`,
  `link_expired`, `telegram_taken`. Успех погашает код, сбрасывает `blocked_at`, сохраняет выбор событий.
- `set_events`: частичное обновление булевых значений по ключам каталога; неизвестный ключ отвергается.
- `unlink`: удаляет строку и её очередь через CASCADE; повтор не создаёт аудит.
- `chats`: Telegram активных администраторов с живой незаблокированной привязкой и включённым `panel_down`.

Аудит: `bot_admin_link_code_created`, `bot_admin_link_created`, `bot_admin_link_removed`,
`bot_admin_link_events_updated`, `bot_notify_test_queued`, сущность `admin_telegram_link`. Нет кода, хеша и Telegram-идентификатора;
у успешной привязки — `admin_id`, `replaced`.

## Каталог и тексты

`notify_catalog.py` разрешает только явный список: `server_down`, `server_recovered`,
`gateway_all_exits_down`, `gateway_failover`, `gateway_exit_recovered`, `jobs_failed`,
`bot_registration_failed`, `server_host_key_mismatch`, `login_locked`, `panel_down`.
По умолчанию включено всё, кроме `login_locked`. `jobs_failed` содержит явный список действий,
а не произвольное совпадение суффикса. `panel_down` не имеет действия аудита и сборщиком не создаётся.

`server_health_changed`: переход из любого состояния кроме down в down → `server_down`;
down → ok/degraded → `server_recovered`. Остальные переходы сообщений не создают.

`notify_texts.py` формирует plain-текст: имя объекта, действие, время события в
`BOT_NOTIFY_TIMEZONE` (UTC), разрешённая причина `unreachable`/`ssh_error`.
Произвольные `meta` и тексты ошибок не вставляются. Имена очищаются от управляющих/bidi-символов,
адресов, почты и длинных чисел, ограничиваются 160 символами. Предел сообщения — 4096 единиц UTF-16.
При заданном адресе панели добавляется ссылка `/audit` с фильтрами `from`/`to` по датам событий.
Диапазон UTC расширяется на день с каждой стороны: журнал трактует даты в часовом поясе браузера.
Если все события сообщения относятся к одной сущности, добавляются `entity_type` и `entity_id`;
для разных сущностей остаётся диапазон дат. Ссылка не выделяет отдельную запись журнала.

## Сборщик

Правило `bot_notify` вызывает `NotifyCollector.run()` раз в `BOT_NOTIFY_INTERVAL_SECONDS` (15 с).
Один проход — одна транзакция: advisory lock PostgreSQL, блокировка курсора, чтение аудита,
`bot_notify_seen`, очередь и курсор; ошибка откатывает всё. SSH и новых задач нет.

`AuditLogRepository.list_for_notify` читает разрешённые действия по `created_at ASC, id ASC`,
исключая seen **до LIMIT** (`BOT_NOTIFY_BATCH`, 500). Окно начинается за
`BOT_NOTIFY_OVERLAP_SECONDS` (2100 с) до курсора: это покрывает поздний commit.
Транзакция старше окна может быть пропущена. Курсор продвигается и без получателей.
Нижняя граница чтения — `max(cursor_at - overlap, started_at)`. Неизменяемый `started_at`
исключает историю до инициализации сборщика, даже внутри overlap. Миграция создаёт курсор;
при его отсутствии первый проход создаёт `cursor_at=started_at=now` без сообщений.
Seen старше двух окон удаляются лишь за пределами текущего окна чтения.

Получатели — активные администраторы с Telegram, без `blocked_at`, включившие ключ события.
До трёх событий одного ключа за проход отправляются отдельно; больше трёх сворачиваются
для каждого получателя: до пяти строк и хвост «и ещё N». Очередь — `notify`, `format=plain`,
приоритет `PRIORITY_NOTIFY=0`; срок — от самого раннего события пачки плюс `BOT_NOTIFY_TTL_HOURS` (24 ч).

## Выдача очереди и heartbeat

Сервисный `claim(..., kinds=None)` выбирает только `news/config`; `notify` требует явного выбора.
Получатель определяется по текущей привязке при выдаче. Просроченное → `skipped/expired`;
отключённый администратор, Telegram, событие или заблокированная привязка → `skipped/no_recipient`.
Текст и формат выдаются из строки очереди. CHECK БД разделяет получателей:
`notify` — только `admin_link_id`, `news/config` — только `user_id`.

`ack blocked` для `notify` выставляет `admin_telegram_links.blocked_at` только если привязка
не обновлялась после claim (`linked_at <= outbox.updated_at`). Claim явно записывает время аренды,
не транзакционный PostgreSQL `now()`, и учитывает `linked_at` видимой привязки. Поздний blocked
закрывает старую строку, но не блокирует новый Telegram. Ack блокирует сначала привязки
в порядке id, затем строки очереди; этот порядок совместим с unlink/CASCADE.
Для обычных сообщений blocked меняет `vpn_users.bot_blocked_at`. Доставка и блокировка не аудируются.

Heartbeat сохраняет `local` в `last_seen_local`, возвращает по HTTP `notify` с
`panel_down_after_seconds` и `chats`, заголовок `Cache-Control: no-store`.
Бот 0.3.0 запрашивает `notify` явно; старый claim без `kinds` получает только news/config.

## Панель и пробная отправка

`/bot/notify` доступна с `bot:notify` (все три роли): привязка, одноразовый код/ссылка с отсчётом,
выбор событий по группам, отвязка с подтверждением, пробная отправка и состояние очереди.
Код не сохраняется в кеше мутаций (`gcTime: 0`); состояние привязки опрашивается во время диалога.
Показаны предупреждения о старом боте, локальном размещении и blocked, список получателей раскрывается отдельно.
В настройках порог задаётся в минутах (1–1440, допускаются дробные значения с целым числом секунд),
API хранит секунды: 90 с отображается как 1,5 минуты и сохраняется точно.
Неизменённые поля следуют свежим настройкам сервера, черновик сохраняется до успешной записи.
PUT событий обновляет кеш значениями ответа. В форме новости можно отправить
HTML-пробу себе при живой привязке и `bot:manage`.

Проба идёт через `queue_test`: plain для проверки уведомлений, проверенный Telegram HTML для новости;
выбор событий не ограничивает пробу. Без привязки — `not_linked`, при blocked — `bot_blocked`.
Постановка пробы аудируется без текста; успешный ответ означает очередь, не доставку.
