# bot — перечень тестов пакета

Запуск: из корня `uv run --project bot pytest`, из `bot/` — как в CI (`bot/CLAUDE.md`). Окружение бота отдельное:
корневой `tests/` aiogram не видит. Тесты панели, которые касаются бота, — `docs/bot/tests.md`.

## Общее

- `conftest.py`: логирование и переменные окружения возвращаются после каждого теста (`_isolated_logging`,
  `_no_ambient_secrets`); фикстура `world` — бот с фейками и хранилищем в `tmp_path`.
- `fakes.py`:
  - `FakeTelegram` — перехват запросов к Bot API через `BaseRequestMiddleware` сессии; журнал `Sent`, `Button`,
    правки кнопок и ответы на callback. Апдейты: `dp.feed_raw_update(bot, update)`; тестовый токен.
  - `FakePanel` — `httpx.MockTransport` с состоянием по `docs/bot/api.md`. Режимы: `unavailable` (503), `dropped`,
    `timed_out`, `unauthorized`, `conflict(reason)`, `rejected(field)`, `rate_limited`, `redirect`.
  - `FakeClock` — виртуальное время (`wall` — для хранилища): три минуты слежения проходят за доли секунды.
- `support.py`: `make_settings`, `make_client`, `make_storage`, `make_heartbeat`, `running_world`, `Person`,
  `World`, `t(key)` (тексты для ожиданий в тестах).

## Файлы

| Файл | Что проверяет |
|---|---|
| `test_dialog.py` | Весь диалог: `/start` с кодом и без, каждый ответ `check_invite`, имя, почта, «Изменить», «Да» и каждый отказ панели (`reason`, 422 по полю), двойное «Да» — один POST, панель упала на «Да» — остаёмся в `confirm`; `/status`, `/help`, ответ на прочее |
| `test_watcher.py` | Итоги `active` (ссылка и заглушка), `failed`, таймаут; расписание; продолжение после «рестарта» на том же хранилище |
| `test_panel_client.py` | Ретраи и паузы, коды ответов, `Retry-After`, редиректы не идут, `http://` только для внутреннего имени, `PANEL_CA_FILE`, настоящий TLS-сервер с сертификатом той же командой openssl, что в установщике; в исключениях нет тел |
| `test_storage.py` | FSM и список регистраций в файле: права 0600, TTL 24 ч, очистка просроченного, стирание строки по завершении диалога |
| `test_hardening.py` | Лимит на человека и его сообщение, очистка просроченного без рестарта, ответы панели не по контракту, зависшее «отправляется», запуск с неверными настройками |
| `test_heartbeat.py` | `getMe` при старте и неверный токен; `POST /heartbeat` каждые 30 с; лог только при смене состояния |
| `test_texts.py` | Каждый ключ есть на русском; подстановки в `t(...)` совпадают с плейсхолдерами (разбор исходников по AST); нет HTML и подсказки `/config` |
| `test_log.py` | Токен, ключ и почта не попадают в вывод за сквозной диалог; маскировка в traceback; `httpx` на WARNING |

## Что ловят

- Опечатка в ключе текста или лишняя подстановка в редкой ветке (сбой, таймаут) — `test_texts.py`, без живого человека.
- Токен и ключ в логах — `test_log.py` прогоняет весь диалог и смотрит на вывод.
- Регистрация, которая не снимается с хранилища, — `test_storage.py` и `test_watcher.py`.
