# bot — Telegram-бот

Отдельный пакет `tollwire-bot` (aiogram 3, long polling). Выдаёт доступ по пригласительной ссылке: человек открывает
бота по ссылке, называет имя и почту, панель регистрирует его (сторона панели — `src/modules/bot`). Бот ходит в панель
только по Bot API (`/api/v1/bot`, заголовок `X-Bot-Key`) и не импортирует `src/`: образ собирается без него,
`tests/unit/test_bot_isolation.py` это проверяет. Ссылку на страницу конфига бот получает от панели (`config-link`)
и только пересылает человеку.

Подробно: `docs/bot-service/dialog.md` (шаги диалога, опрос готовности, команды, тексты, отказы), `docs/bot-service/panel-client.md`
(клиент панели, TLS, ретраи, коды), `docs/bot-service/tests.md` (перечень тестов). Контракт панели — `docs/bot/api.md`,
`docs/bot/registration.md`, `docs/bot/config-page.md` (страница конфига).

## Файлы

| Путь | Что |
|---|---|
| `src/tollwire_bot/config.py` | `Settings`: `TELEGRAM_BOT_TOKEN`, `BOT_API_KEY` (SecretStr), `PANEL_URL`, `PANEL_CA_FILE`, `STATE_DIR` (`/data`), `LOG_LEVEL` |
| `panel.py` | `PanelClient` — единственный путь бота к панели (httpx и stdlib), ретраи, коды ответов → исключения; `config_link` → `ConfigLink` (адрес в `repr` не показывается) |
| `texts.py` | Все тексты: `TEXTS[key]["ru"]`, `t(key, lang, **kw)`, `format_date`. `parse_mode` не задан |
| `validation.py` | Имя (1–64 после strip, без Cc/Cf/Cs/Zl/Zp), почта (regex, до 100), код `start` (`[A-Za-z0-9_-]{1,64}`) |
| `storage.py` | `SqliteStorage(BaseStorage)`: состояние диалога и список регистраций в одном файле |
| `dialog.py` | Регистрация: `/start <код>`, состояния `name → email → confirm → submitting`, кнопки «Да» / «Изменить» |
| `commands.py` | `/status`, `/config`, `/help`; всё прочее — ответ по умолчанию (регистрируется последним) |
| `refusals.py` | `CONFIG_REFUSAL_TEXT`: причина 409 `config-link` → ключ текста (`config_unavailable`, `config_no_access`, `config_not_ready`, `config_not_configured`) |
| `watcher.py` | `Watcher`: опрос `GET /registrations/{id}` и итог человеку (при `active` — ссылка из `config-link`); список ожидающих лежит в хранилище |
| `heartbeat.py` | `getMe` при старте, `POST /heartbeat` каждые 30 с; лог только при смене состояния |
| `log.py` | `RedactingFormatter` (адрес страницы конфига `…/c#…` маскируется целиком), `configure_logging` (один обработчик на корне) |
| `app.py` | `build_dispatcher(settings, panel, storage, *, sleep, clock)`, `UserThrottle`, фильтр личных чатов |
| `__main__.py` | Сборка и запуск: `getMe`, меню команд (`status`, `config`, `help`), превью ссылок выключено (`DefaultBotProperties(link_preview_is_disabled=True)`), фоновые задачи, `/tmp/alive`, очистка по часу, SIGTERM |
| `__init__.py` | Только `__version__` |
| `Dockerfile`, `docker-compose.yml`, `.env.example`, `install-bot.sh`, `pyproject.toml`, `uv.lock` | Образ, вариант «другой сервер», установщик, зависимости |

## Диалог

- `/start <код>`: код проверяется в панели (`invites/check`), затем имя → почта → «Да» / «Изменить» → `POST /registrations`.
  Отказы и их тексты — в `docs/bot-service/dialog.md`.
- После «Да» бот опрашивает регистрацию через 2, 5 и 10 с, затем каждые 10 с, до 180 с от регистрации.
  Итог: `active`, `failed` или таймаут («ещё готовится, загляните через несколько минут»).
- `active` → `POST …/config-link` → «Доступ готов до ДД.ММ.ГГГГ. Ваша страница с конфигом: <адрес>» с предупреждением не
  пересылать. `not_ready`, 404 и сбои панели — следующий опрос; `config_unavailable`, `no_access`, `not_configured` —
  свой текст, слежение заканчивается. Сбой отправки — на следующем опросе выпускается новая ссылка, прежняя гаснет.
- `/config` — новая ссылка на страницу, прежняя гаснет. `/status` — имя, срок, протокол и подсказка про `/config`;
  `/help` — справка; остальное — «Не понимаю…». Бот отвечает только в личных чатах.
- Больше 60 событий в минуту от одного человека отбрасываются молча; сообщение о лимите — раз в минуту.

## Состояние на диске

- SQLite `state.sqlite3` в `STATE_DIR` (`/data`, том `bot_data`). Файл и журнал создаются с правами 0600 до первой
  записи; `secure_delete` стирает и страницы.
- Имя и почта лежат на диске до конца диалога. Срок записи диалога — 24 ч от последней записи; регистрация в ожидании
  живёт 24 ч от начала слежения.
- Просроченное удаляется при каждой записи, при старте и раз в час (`purge_loop`). Завершённый диалог не оставляет строки.
- Опрос продолжается после рестарта бота: отсчёт идёт от исходного момента регистрации.

## Безопасность

- Токен Telegram и ключ бота: на сервере панели — `.env.bot` (0600, только у сервиса `bot`), на другом сервере —
  `bot/.env` (0600). В `.env.prod` попадает только `COMPOSE_PROFILES=bot`. Ключ и токен не передаются аргументами
  команд: curl читает их из stdin, ввод скрытый.
- Логи: `RedactingFormatter` вырезает точные значения секретов и шаблоны токена и ключа, в том числе в traceback.
  В логи не попадают тексты сообщений, имя, почта, код приглашения, тела запросов и ответов, `detail` ответа 422.
  Логгеры `httpx` и `httpcore` — WARNING. Исключения `PanelClient` несут только код и `reason`.
- Ссылка на конфиг — секрет: `log.py` маскирует адрес `…/c#…` целиком, `ConfigLink.__repr__` адреса не показывает,
  превью ссылок выключено (`link_preview_is_disabled`), чтобы Telegram не открывал страницу сам.
- `parse_mode` не задан: имя и почта выводятся обычным текстом (иначе разметка в имени ломала бы подтверждение).
- TLS: `certifi` плюс `PANEL_CA_FILE` (свой сертификат панели, в дополнение к штатному хранилищу). Флаг
  `VERIFY_X509_STRICT` снят только при заданном `PANEL_CA_FILE`: сертификат закреплён по отпечатку. Редиректов нет
  (`follow_redirects=False`). `http://` — только для имени без точки (`api` в сети compose).
- Ввод человека проверяется здесь по очевидному, окончательно — в панели. События одного человека идут по очереди
  (`SimpleEventIsolation`): два «Да» подряд дают один запрос.

## Установка

- На сервере панели: `deploy/bot.sh` (общий код `install.sh` и `./panel bot`), сервис `bot` в `docker-compose.prod.yml`
  (профиль `bot`, `read_only`, `cap_drop: ALL`, сеть `edge`, том `bot_data`).
- На другом сервере: `bot/install-bot.sh`. Пишет `bot/.env`, а если сертификат панели самоподписанный — и
  `bot/certs/panel-ca.pem`, только после сверки отпечатка. Запускает `bot/docker-compose.yml`.

## Healthcheck

Бот раз в 10 с touch-ит `/tmp/alive`, пока последний ответ панели на heartbeat не старше 90 с. Compose проверяет, что
файл не старше 90 с.

## Тесты

- `bot/tests`: `FakeTelegram` (перехват запросов к Bot API) и `FakePanel` (`httpx.MockTransport`). Без сети и без
  панели. Из корня: `uv run --project bot pytest`.
- Проверки как в CI (задача `bot`), из `bot/`: `uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest -q`.
- Тесты панели, которые касаются бота (изоляция, контракт клиента, CLI, установщики), — в корневом `tests/`, см.
  `docs/bot/tests.md`.

## Не входит

Нет рассылок и очереди сообщений, уведомлений администратору,
сообщения администратору о недоступной панели, установки по SSH и экрана в панели.

## Принятые компромиссы

- Бот в сети `edge`, а API доверяет `X-Forwarded-For` из `EDGE_SUBNET`: скомпрометированный бот может подменить IP в
  логах и в лимитах по IP. Лимит по ключу от IP не зависит.
- Неудачная смена ключа (`./panel bot key`, новый ключ не вышел на связь): старый ключ не отзывается и остаётся
  действующим, пока его не отзовут вручную (`./panel bot revoke`).
- Проверки в установщиках через `curl -f`: в `install-bot.sh` код выхода 22 (любой HTTP-ошибки, в том числе 5xx)
  выводится как «ключ неверный или отозван», а сбой сети — как «панель не отвечает».
- Профиль `bot` без `.env.bot` на сервере панели: контейнер не получает настроек, выходит с ошибкой и по
  `restart: unless-stopped` перезапускается по кругу.
- Повтор `config-link` при 502/503/504 и при сетевом сбое выпускает ещё одну ссылку; прежняя, не доставленная, гаснет.
